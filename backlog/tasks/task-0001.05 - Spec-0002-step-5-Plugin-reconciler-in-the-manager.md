## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The manager must run each declared plugin and hand it the Devices declared for it, so Git owns device naming as it does for Zigbee2MQTT.

Scope:
Write `PluginReconciler`, `internal/render/plugin.go` (config Secret and Deployment), and the `Ready` reasons, with an envtest suite. Add `config/samples`.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. internal/render/plugin.go: PluginLabels, PluginDevice, PluginConfig (devices.json, contract 1, sorted by id), PluginConfigSecret (<plugin>-config, owned), PluginDeployment (1 replica, Recreate, config-hash annotation, OIKADE_* env, config and optional user-Secret mounts, hostNetwork + ClusterFirstWithHostNet, no SA token, non-root, read-only root FS with an emptyDir /tmp). Unit test TestPluginDeployment and TestPluginConfig.
2. internal/controller/plugins: PluginReconciler lists Devices (sorted by name, first wins on duplicate id), applies the Secret and Deployment, checks spec.secretRef with Get, sets status.devices/configHash and Ready (DuplicateDevice > SecretNotFound > Available/Progressing). Watches Devices (by pluginRef) and the user Secret (Plugins in the namespace naming it). Owns Deployment and Secret.
3. Pass MQTTURL from cmd/main.go; RBAC markers for devices, secrets and deployments; make manifests.
4. envtest suite covering Secret/Deployment shape, hash restart, hostNetwork, Ready reasons.
5. Samples already include a Plugin and a plugin Device (from TASK-0001.03); verify they apply against the CRDs.

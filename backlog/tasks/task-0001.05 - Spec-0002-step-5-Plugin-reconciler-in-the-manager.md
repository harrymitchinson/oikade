## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Code review of 290809e found 7 issues, all addressed:
- The Deployment and config Secret are now <plugin>-plugin and <plugin>-plugin-config, so a Zigbee2MQTT with the same name can't fight over them. The reconciler also refuses (Ready=False NameConflict) to apply over an existing object it doesn't control, or when spec.secretRef names its config Secret.
- observedGeneration only advances when reconcile succeeds.
- A Deployment missing from the cache right after create reads as Progressing, so DuplicateDevice and SecretNotFound show on the first pass.
- pluginsForSecret logs List errors.
- The pod template carries plugins.oikade.dev/secret-version (the user Secret's resourceVersion), so rotating keys restarts the plugin.
- Apply and DeploymentAvailable moved to internal/controller/shared for the Bridge, Zigbee2MQTT and Plugin controllers. setReady and the duplicate-id loop stay per controller: each is bound to its own type.
Local builds need GOTOOLCHAIN=go1.26.0 CGO_ENABLED=0 (Homebrew Go 1.27.2 and the macOS 27 SDK break cgo links and golangci-lint). CI isn't affected.
<!-- SECTION:NOTES:END -->

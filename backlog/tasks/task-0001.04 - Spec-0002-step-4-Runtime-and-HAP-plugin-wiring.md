## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Runtime and every HAP pod run the hub, so both must follow plugin topics for plugin devices to reach automations, metrics and HomeKit, including when the runtime is down.

Scope:
- Add the Plugin reconciler in `internal/hub`.
- Add RBAC in `config/runtime/role.yaml` and `internal/render/hap.go`.
- Add the status writer `PluginError` reason and the two metrics.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Runtime and HAP hubs now follow plugins. The hub runs a Plugin controller next to the Zigbee2MQTT one, starting a plugin.Instance on oikade/v1/<ns>/<plugin> for each Plugin and declaring the Devices whose spec.plugin points at it (first by name wins on duplicate ids). The status writer adds Resolved=False PluginError carrying the plugin's message (cut to 256 bytes, UTF-8 safe), and NoDriver now names whichever source the Device uses. The runtime exports oikade_plugin_up and oikade_plugin_rejected_messages_total. The runtime ClusterRole and HAP Roles get read-only plugins access.

Tests: an envtest+mqtttest integration test (TestRuntimePluginDevices) covers retained topics to Resolved=True with capabilities, PluginError, an Automation /set on the plugin topic, both metrics, undeclared count and offline. Also added a status compute table test, a collector test and a HAP Role assertion. README Metrics lists the new metrics.

Follow-ups: the Pi guide's NoDriver row and the rest of the plugin docs belong to TASK-0001.09.

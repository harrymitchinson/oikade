## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Go is the first plugin language, so it needs an SDK that handles the Last Will, re-announcing, /set dispatch and SIGTERM, the hard parts of the contract.

Scope:
- sdk/plugin: Environment, ReadEnvironment, ReadDevices, ReadSecret, RelayCapability, Options, Start, SetDevices, SetState, UpdateState, SetAvailability, State, Close, Handler and Run, as in doc-0006 API. It ports sdk/typescript/src/plugin.ts and environment.ts.
- It uses internal/mqtt (with the options from TASK-0008.01) and internal/capability. Exported signatures must not mention internal types.
- Use a random client ID, oikade-plugin-<12 hex>.
- SetState validates with capability.Validate and refuses unannounced capabilities.
- /set handling is serialised per device. Log with log/slog JSON to stderr, using the messages in doc-0006 Observability.
- Tests: integration with mqtttest for announce order, republish after a reconnect, and close never being followed by online. Unit tests port sdk/typescript/test.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 On every connection the SDK publishes status online, then devices (once set), then availability and state, all retained
- [ ] #2 After a broker restart, all retained topics are republished without the plugin calling anything
- [ ] #3 Close publishes status offline and disconnects cleanly; online is never published after Close starts
- [ ] #4 SetState returns an error and publishes nothing for an unannounced capability or an invalid value
- [ ] #5 Run exits 0 on SIGTERM and 1 on a startup error
<!-- AC:END -->

## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The hub hard-codes zigbee2mqtt.Instance and keys instances by bare NamespacedName, so a Plugin and a Zigbee2MQTT with the same name would collide. This refactor lets a second driver plug in without changing Zigbee2MQTT behaviour.

Scope:
Add `InstanceKey` and the internal `instance` interface in `internal/hub`, and thread `InstanceKey` through `Store`, `driver.Sink.Undeclared`, the metrics collector and `status`. Zigbee2MQTT behaviour is unchanged, and the existing tests stay green.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Add driver.InstanceKey{Driver; types.NamespacedName} with Zigbee2MQTT/Plugin driver names and a Label() for metrics (name for zigbee2mqtt, plugin/<name> otherwise). It lives in internal/driver, not internal/hub as the spec says, because driver.Sink.Undeclared takes it and hub already imports driver.
2. Change driver.Sink.Undeclared, hub.Meta.Instance, Store.SetDevices/undeclared/UndeclaredCounts to InstanceKey. Decoders keep Key as NamespacedName and wrap it with their driver name when calling Undeclared.
3. Hub: internal instance interface (Set, SetDevices, Stop), instances map[InstanceKey]instance, ensure/stop take InstanceKey so a Plugin reconciler can share them in step 4; compile-time checks for both decoders.
4. Metrics collector writes instance=key.Label(); status writer unchanged (NoDriver wording is step 4).
5. Tests: TestInstanceKeySeparatesDrivers (store entries and undeclared counts), collector label test; mechanical signature updates in existing tests only.
6. CGO_ENABLED=0 make test and lint.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
InstanceKey lives in internal/driver (driver.InstanceKey), not internal/hub: driver.Sink.Undeclared takes it and hub already imports driver, so hub can't own it.
Decoders keep Key as types.NamespacedName and wrap it with their driver name when they call Undeclared, so their error and log text is unchanged.
AC3: no test assertion changed. Four existing test files needed call-site type updates only (recorder Undeclared signatures, SetDevices(z2m key) in store_test and engine_test), because the signatures changed.
Hub.ensure now takes a key, a current check and a start func, ready for the Plugin reconciler in step 4. Compile-time checks assert both zigbee2mqtt.Instance and plugin.Instance satisfy the internal instance interface.
Docs: no user-facing change in this step. Plugin values of oikade_undeclared_devices only appear once Plugins exist, and the README metrics row is updated in TASK-0001.09.
Verified: CGO_ENABLED=0 make test passes (including envtest suites, runtime and hap), CGO_ENABLED=0 GOTOOLCHAIN=go1.26.0 make lint reports 0 issues. New tests: internal/hub TestInstanceKeySeparatesDrivers, internal/metrics TestUndeclaredInstanceLabel.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Made the hub driver-agnostic. Added driver.InstanceKey{Driver, NamespacedName} with Label() (bare name for Zigbee2MQTT, plugin/<name> otherwise) and threaded it through hub.Meta.Instance, Store.SetDevices, Store.Undeclared/UndeclaredCounts, driver.Sink.Undeclared and the metrics collector. The hub keeps map[InstanceKey]instance behind an internal Set/SetDevices/Stop interface, and ensure/stop are generic so the step-4 Plugin reconciler can share them. Zigbee2MQTT behaviour and oikade_undeclared_devices labels and values are unchanged. Tests: TestInstanceKeySeparatesDrivers (store entries and undeclared counts don't collide), TestUndeclaredInstanceLabel (metric labels). make test and make lint are clean. Deviation from the spec: InstanceKey is in internal/driver rather than internal/hub, to avoid an import cycle.

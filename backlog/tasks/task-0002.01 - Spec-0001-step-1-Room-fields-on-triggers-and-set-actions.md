## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Automations can only name one Device per trigger or set action. The API must accept a room in either place without invalidating existing Automations, before the engine can act on it.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 An Automation with exactly one of device or room on each trigger and set action is accepted; neither or both is rejected
- [x] #2 Existing device-only Automations and samples still apply
- [x] #3 Compile accepts room triggers and actions and rejects a trigger or action with neither
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [x] #1 Tests pass
- [x] #2 Documentation updated
- [x] #3 No regressions introduced
<!-- DOD:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. api/home/v1alpha1/automation_types.go: make device optional (omitempty) on Trigger and SetAction, add room (MinLength=1, optional), add XValidation has(self.device) != has(self.room) on both structs; update doc comments per spec API section.
2. make manifests generate (no hand edits to generated files).
3. internal/engine/compile.go: action gains room; Compile rejects triggers[i]/actions[i] with neither device nor room; carries room into action.
4. internal/engine/engine.go execute: skip set actions with a room (no-op until step 2) so a room action never calls Setter.Set with an empty device name. Room triggers already never match (Device is empty).
5. Tests: TestCompileRoom in internal/engine; envtest cases in internal/controller/home for device-only, room-only, neither and both on triggers and set actions.
6. make lint-fix; CGO_ENABLED=0 make test.

Revised: also confirm the existing Automation sample still applies with a throwaway envtest (not kept).
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
- Added room plus the has(self.device) != has(self.room) rule to Trigger and SetAction. make manifests generate changed only config/crd/bases/home.oikade.dev_automations.yaml; no deepcopy change because the new fields are strings.
- Compile rejects triggers[i]/actions[i] that set neither device nor room, and carries room into action.
